# GoNoGo — project guide for Claude Code

GoNoGo is an AI launch-decision agent for retailers, built for the Google Cloud AI Builder Cup 2026
(Retail & Commerce theme). A seller proposes a new product; specialist agents check it against the
shop's own sales and inventory (BigQuery) and the live market (Gemini + Google Search), and a verdict
agent returns Go / No-go / Go with conditions, with reasons that each link to evidence.

**Deadline: submission on 18 Oct 2026.** Prefer small, working, deployed steps over big rewrites.
The full feature plan is in `docs/BUILD_PLAN.md`. Work one batch at a time and stop after each batch
so the owner can test locally and deploy.

## Stack (fixed: do not substitute)
- Python 3.11, FastAPI, one Cloud Run service (API + static pages)
- Gemini on Vertex AI via `google-genai` (`vertexai=True`, location `us-central1`), model from `GEMINI_MODEL`
- Grounding with Google Search for market research
- BigQuery for all business data
- Frontend: plain HTML + CSS + JavaScript in `backend/static/`. **No React, no build step.**
- Auth: Application Default Credentials only. **Never** put API keys or service-account JSON in the repo.

## Commands
Run from `backend/` with the virtual environment active.
- Install: `pip install -r requirements.txt`
- Run locally (macOS/Linux): `GOOGLE_CLOUD_PROJECT=gonogo-511 uvicorn main:app --reload --port 8080`
- Run locally (Windows PowerShell): `$env:GOOGLE_CLOUD_PROJECT="gonogo-511"; uvicorn main:app --reload --port 8080`
- Run without Google Cloud (sample data): set `GONOGO_MOCK=1` as well
- Demo cases from the terminal: `python test_local.py`
- Deploy: `gcloud run deploy gonogo --source . --region asia-south1 --allow-unauthenticated --max-instances=2 --service-account gonogo-run@gonogo-511.iam.gserviceaccount.com --set-env-vars GOOGLE_CLOUD_PROJECT=gonogo-511`
  (the live site is open: the access gate is off since 18 Oct 2026; add `,GONOGO_ACCESS_CODE=<code>` to turn it back on)
- Access gate (`backend/access.py`): with `GONOGO_ACCESS_CODE` set, pages redirect to `/access` and `/api/*` answers 401 until the
  code is entered (HttpOnly cookie = HMAC of the code, 30 days; 10 wrong tries per IP per 10 min). Unset = open. Never commit the code.
- Limits (`backend/limits.py`), per IP address per rolling hour: 10 product checks (`/api/evaluate`, `/api/evaluate/stream`),
  30 photo reads (`/api/autofill`), 20 settings saves (`PUT /api/settings`); 429 with a plain message. In memory per
  instance, so up to 2x with 2 instances. Store-page URLs are anchored to `https://<store host>/` before the server fetches them.

## Rules for all code
1. **Numbers are calculated in code or SQL, never generated by Gemini.** Gemini understands, searches and
   explains; it must not invent figures. Prompts pass numbers in and say "never invent numbers".
2. **The go / no-go verdict is decided by rule checks in code** (`agents/verdict.py`). Gemini explains it and may not change it.
   Every reason must support the verdict.
3. **Every agent returns `(result, evidence)`.** Evidence shape: `{"summary": [[label, value]], "tables": [{title, columns, rows}], "links": [{title, url}], "note": str}`.
   A table cell may be `{"text", "url"}` to render a link. The page renders evidence generically.
4. **One failed agent never crashes a request.** The orchestrator marks it `failed` and the others carry on.
5. **Never invent URLs.** Competitor links come from pages Google Search returned, or are clearly labelled store searches.
6. Rupees everywhere with the ₹ sign and Indian digit grouping (₹3,51,000). Use `agents/common.inr`.
7. Keep mock mode working: every new BigQuery query or Gemini call needs a matching function in `agents/mock.py`.
8. Plain, short user-facing copy. Errors say what went wrong and how to fix it.
9. Keep the page usable at phone width and in dark mode (colours come from tokens in `app.css`).

## Current state
- Batch 1 done: Urban Loom dataset (`gonogo-511.gonogo_shop`, asia-south1), Discovery + Business pages, rules saved in BigQuery.
- Sidebar navigation (shared.js) on every page: Discovery, then Business, Products, Inventory, Sales, Returns,
  Customers, Suppliers. The six shop pages share `data.html`/`data.js`; their data comes from `agents/pages.py`
  (`GET /api/pages/<name>`). The Inventory page (Batch 2a) is done; `/inventory?sku=...&status=...` pre-filters it.
- Batch 3a done: Discovery starts from a photo (`POST /api/autofill`, `agents/autofill.py`); the seller enters the cost
  price and gets a suggested selling price from `sql/price_suggestion.sql`.
- Discovery is a chat: each question adds a user bubble and a bot answer to `#thread` (LiveAnswer in agents.js streams
  one line per agent, then folds them); the answer shows verdict, key numbers and reasons. Less important material
  (similar products, rule checks, sales chart, each agent's evidence) goes to the References panel `#refs` on the right.
- GoNoGo, the buying buddy (the tool speaks as itself; compass mark = logo + favicon; agents.js `gogoHTML`/`gogoSay`, index.html `gogoReaction`): greets you on the
  centred empty page, says "On it!" when you ask, and reacts to each verdict in plain words.
  Fixed wording; numbers from code. (The follow-up reply chips were removed at the owner's request.)
- The page scrolls (not an inner box); the search box is `position: fixed` and lined up with the chat by `placeComposer`.
- Chat touches on Discovery: Enter sends (Shift+Enter new line) and the box grows; the go button becomes Stop
  (AbortController, the server cancels the run); Copy / Retry / References under each answer; "↓" jump-to-latest;
  References can be closed; greeting by time of day + shop name. Conversations are saved in this browser
  (`localStorage` "gonogo.checks.v1", last 12, photos only as thumbnails) and listed as "Recent checks" in the sidebar
  (shared.js `recentChecksHTML`); `/?c=<id>` reopens one.
- Discovery is a single search-style column (`.disc`): one composer box (description in `#name`, Photo button,
  Cost/Price, round go button), details/department/category tucked under "Details"; results stream below it.
  Products that don't fit come with Gemini's one-line `reason` in the shop's own terms.
- Photo step finds several products: `/api/autofill` returns `items` (n, box [ymin,xmin,ymax,xmax] on 0-1000,
  fits_shop, department/category, price suggestion each) + `selected`. Discovery draws numbered boxes and a pick list;
  the picked product is cropped out of the photo (`cropTo`) and only that crop goes to `/api/evaluate`.
- The shop's own catalogue decides fit first: `catalog.match_catalog` (word overlap, in code) — if the product closely
  matches an active product (score >= 0.6), it fits, in that product's department/category, whatever Gemini said.
  Colours are left out of the score (names are "Style - Colour"; colour words come from the catalogue + `_COLOURS`), so
  "Longline Coat - Black" matches "Longline Coat - Olive", not "Longline Gym Tee - Black". Same product = same style and
  colour (score >= 0.85): its own stock is checked. Same style, other colour (`same_style_variants`): if every colour of
  that style is dead stock, `existing_stock` fails hard (No-go); some dead = soft warning; all selling = pass.
  Demand lists "your closest products" with their sales. Discovery sends `department: null` unless one was chosen.
- Sales-speed bands: below `min_velocity` (0.7x the shop average) = hard fail (No-go); 0.7x-1x = soft `velocity_avg`
  (Go, with conditions, and Vera says what would need to change); 1x or more = pass.
- Hard rule `fits_shop` (Product agent): a product the shop doesn't sell (e.g. a brass diya) is always NO_GO and
  the comparison agents are skipped. If the Product agent fails twice, the rule fails closed ("couldn't check").
- Shop profile page (`/shop`) is reached from the shop card at the bottom of the sidebar (name + tagline), not the list: name, tagline, description, customer, positioning, style, "never sells". Saved in
  `settings.profile_json` (added on first read by `sql/settings_migrate.sql`). `agents/settings.shop_brief` turns it into
  the definition the Product (photo + verdict) and Verdict agents judge against. `PUT /api/settings` saves only the
  fields sent, so the Business page (rules) and Shop profile page never overwrite each other.
- Agent crew (static/agents.js): each agent has a character (Iris, Scout, Ledger, Echo, Penny, Vera) on a live board.
  Discovery calls `POST /api/evaluate/stream` (NDJSON: start/done/failed/skipped per agent, then result);
  `orchestrator.evaluate(req, emit=...)` sends the events; `agent_summary` builds each card's line in code.
  The quips are fixed text, never numbers. `/api/evaluate` still returns the whole result in one go.
- Experiment budget (agents/budget.py, sql/budget_inputs.sql, `GET /api/budget`): monthly profit run-rate (90 days) x
  `experiment_pct`, x growth and slow-stock factors, split by `launches_per_month`. Hard rule `budget` (Penny):
  opening stock + launch cost must fit the per-launch budget. Shown on the Business page.
- Similar products online are real product pages: `market.find_product_pages` runs one grounded search per marketplace
  (Myntra, Flipkart, Ajio, Amazon.in) in plain text (JSON-only prompts search less) and keeps only product-page URLs
  that Search returned (`STORE_PAGES` patterns). Each page's own title, price (schema.org JSON-LD), picture (og:image)
  and rating (only with a rating count) are read from the page; Ajio blocks reading, so its rows keep link + name only.
- Every competitor row opens that exact product: store-search and category pages are never listed (`is_product_page`),
  a Gemini-named product links to a page only when `_page_match` agrees (3+ words covering most of the page's name),
  and the row takes the page's own name and price. Mock mode still shows labelled store searches.
- Similar products online: rating + review count only when Google results show them (Gemini told never to guess);
  picture + rating from the store page itself (og:image, JSON-LD) only when Search returned a real product page;
  otherwise a store-initial tile. `market.SSL` uses certifi: python.org Python on macOS has no CA certificates,
  which silently stopped grounding redirects resolving (every competitor fell back to a "Search" link).
- Sidebar: Your shop pages + Recent checks scroll; Discovery and the shop card stay pinned at the bottom. Recent checks
  shows the latest 3 (localStorage `gonogo.checks.v1`, up to 30); search / View all open `#checks-modal` (search,
  All/Go/Conditions/No-go filters). A bin on each check deletes it (asks first; deleting the open one starts a new check).
- SOP on Discovery: the `#sop-open` button (top right, next to References; icon-only in the phone top bar) opens
  `#sop-modal`, 7 short slides (`SOP_SLIDES` in index.html) on how to use GoNoGo; a dot shows until it's opened once. Hidden once a conversation starts (`.disc.asked`).
  It opens with a 4-slide story ("Why GoNoGo") told through Priya, a shop owner: poses cut from
  `character_style_spritesheet.png` into `backend/static/sop/priya-*.png` (phone, curious, notes, sad, sigh, happy).
